# Windmill Scripts & Flows

Single-page reference for the Windmill sync lifecycle. See
`.agents/rules/project.md` for the cross-cutting rules (auto-generated
file list, pre-commit discipline, survey-existing-patterns).

## Workspace layout

- `f/<area>/<name>.py` &mdash; scripts (one `main` per file).
- `f/<area>/<name>.script.yaml` &mdash; script schema (auto-generated).
- `f/<area>/<name>.script.lock` &mdash; pinned dependency snapshot
  (auto-generated).
- `f/<area>/<name>.flow/flow.yaml` &mdash; flow definition.
- `f/<area>/<name>.flow/*.inline_script.py` &mdash; inline script
  modules for flows (live next to the `flow.yaml`).
- `dependencies/<name>.requirements.in` &mdash; per-workspace dep lock
  used by `.script.lock` files (auto-generated from `pyproject.toml`).
- `wmill-lock.yaml` &mdash; hash table mapping script/flow paths to
  their content hashes. Auto-regenerated by `wmill sync push`.
- `pixi.lock`, `uv.lock` &mdash; resolver outputs (regenerated by
  `pixi install` and `pixi run deps`).

The single Windmill command for script/flow metadata is
`wmill generate-metadata --workspace localdev --yes`. It produces
`.script.yaml`, `.script.lock`, `.flow/flow.yaml`, and
`.inline_script.lock` for everything in `f/`.

## Lifecycle: create a new script

1. Write `f/<area>/<name>.py` with `def main(...): ...` and a header
   `# requirements: project` (or a named requirements set).
2. Run `wmill generate-metadata --workspace localdev --yes`.
3. Add `summary` and `description` to the generated `.script.yaml`.
   Leave `schema` / `required` / `lock` as-is.
4. Run `pixi run check`.
5. Run `pixi run dev-run f/<area>/<name>` (no `.py` ext) to smoke-test,
   with `--args <json>` if the script takes arguments.

## Lifecycle: edit an existing script

1. Edit the `.py` only.
2. Run `wmill generate-metadata --workspace localdev --yes` (this
   rewrites `.script.yaml` and `.script.lock`; only `summary` and
   `description` survive round-trips).
3. Run `pixi run check` and `pixi run dev-run` to verify.

## Lifecycle: add a new dependency

1. Add the package to `pyproject.toml` `[project].dependencies`.
2. Run `pixi install` (updates `pixi.lock`).
3. Run `pixi run deps` (regenerates `dependencies/*.requirements.in`
   and `uv.lock`).
4. Run `wmill generate-metadata --workspace localdev --yes` for any
   script that imports it (adds the package to `.script.lock`).
5. Run `wmill sync push` to refresh `wmill-lock.yaml` hashes.

## Lifecycle: edit or create a flow

1. Edit `flow.yaml` (or create `<name>.flow/flow.yaml`).
2. Run `wmill generate-metadata --workspace localdev --yes` to
   regenerate the flow's `.inline_script.lock` files and module IDs.
3. Run `pixi run check` and `pixi run dev-run` to verify.

## Auto-generated file patterns

| Pattern                          | Generator                                            |
| -------------------------------- | ---------------------------------------------------- |
| `f/graphql/api_client/*`         | `pixi run graphql`                                   |
| `f/graphql/schema.gql`           | `pixi run graphql`                                   |
| `**/*.script.yaml`               | `wmill generate-metadata --workspace localdev --yes` |
| `**/*.script.lock`               | `wmill generate-metadata --workspace localdev --yes` |
| `**/*.inline_script.lock`        | `wmill generate-metadata --workspace localdev --yes` |
| `**/*.flow/**/flow.yaml`         | `wmill generate-metadata --workspace localdev --yes` |
| `dependencies/*.requirements.in` | `pixi run deps`                                      |
| `wmill-lock.yaml`                | `wmill sync push`                                    |
| `pixi.lock`                      | `pixi install`                                       |
| `uv.lock`                        | `pixi run deps`                                      |

If a diff shows up in one of these, your work is incomplete — run the
matching generator and re-stage. Do not commit manual edits.

## Common failure modes

- **Hand-written `.script.yaml` is missing markers.** The auto-generated
  style uses `originalType`, `default: null`, and `format: resource-*`
  markers. Hand-written YAML passes a quick look but is rejected by the
  Windmill UI. Always run `wmill generate-metadata` and only edit
  `summary` / `description` afterwards.
- **Manual `.script.lock` edits get overwritten.** `wmill sync push` and
  `wmill generate-metadata` both rewrite `.script.lock` from scratch.
  Any line you hand-add (e.g. `nltk==3.9.4`) disappears on the next
  sync. Add the dep to `pyproject.toml` instead and let the generator
  add it.
- **Lock file `workspace-dependencies` hash desync.** `.script.lock`
  files contain a `# workspace-dependencies: project:<hash>` line that
  pins them to a specific `dependencies/project.requirements.in`
  content. If you re-order or hand-edit the lock lines, the hash
  becomes wrong and Windmill will reject the lock.
- **Hook reformatted your file mid-commit.** `pixi run prek` runs
  `ruff format` and aborts the commit if it changes anything. Re-stage
  the file (`git add <file>`) and retry. Do not use `--no-verify`.
- **`basedpyright` missing-import for a pixi-installed package.** The
  typechecker may not pick up the pixi env's site-packages. Run with
  `--pythonpath .pixi/envs/default/bin/python` to confirm before
  treating it as a real code issue.
